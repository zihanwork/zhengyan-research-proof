# AI 使用与验证记录

记录日期：2026-10-29（Asia/Shanghai）。不把本次开发中的模型辅助与产品运行时模型混为一谈。

## 使用了什么 AI

- **Codex（当前会话）**：场景选择、工作流与非目标定义、UI/后端/适配器/测试/文档编写、错误定位和修正。
- **iFinD 官方技能**：读取实际能力与调用参数，完成本地真实报价工具调用；Web 端实现对应 MCP HTTP 只读协议。
- **Sites**：提供项目脚手架、源码同步与运行部署能力，不宣称 Sites 自带本产品 LLM 推理。
- **产品运行时**：OpenAI Chat Completions 兼容接口，由服务端或用户页面临时提供模型配置。模型 ID 与 usage、响应 ID、延时、结构化输出会保存在 `model_record`。没有密钥时明确停止自定义 AI 规划，不以规则或预设示例冒充 AI。

没有使用图像生成、自动交易或任何交易账户工具。

## AI 参与与人机边界

AI 生成结构化计划（原文、指标、运算符、阈值、歧义）。执行器验证结构、构建白名单数据请求、按确定性公式核验。人先确认计划，再复核每条核验记录。

原文是不可信输入，系统提示禁止执行其中命令；输出只允许白名单指标。模型不能发起任意 URL、修改数据库、执行代码、读取密钥或操作交易。UI 仅显示结构化结果，不收集或展示隐藏推理过程。

## 可检查的提示词与使用记录

- 系统提示全文及版本：`lib/model.mjs` 的 `PLAN_SYSTEM`、`PROMPT_VERSION`。
- 输入示例：`data/sample-run.json.input`。
- 校验函数：`validatePlan`，逐字引用、指标枚举、比较枚举与数值类型检查。
- 模型使用记录：在线运行的 JSON 导出 `model_record`，带模型 ID、prompt 版本、时间、token usage（服务如提供）、响应 ID 与实际结构化输出。运行记录与输入由服务端签名计划携带。
- 数据凭证：JSON 导出 `sources[].raw`、`request_id`、`params`、`fetched_at`、`data_at`。
- 复核与纠正：`claims[].review_note`、`review_log`。复核人当前只有本地标签，没有认证身份，不能宣称不可否认性。

## 实际发现并修正的问题

| AI/初版产生的问题或不合理假设 | 如何验证 | 修正 |
| --- | --- | --- |
| 安装/接入可能仅以文件存在当成功 | 本地真实 `listTools('stock')` 与报价调用 | 分别验证文件与实际通信；无密钥不能发占位请求 |
| 单靠 HTTP 200 判断取数成功 | 文档明确业务错误码且测试注入 `code=4001` | 同时验证 HTTP、业务码、数组结构；无隐藏重试 |
| 假设两源价格一样即可“核验通过” | 真实返回里扶摇就绪时间与 iFinD 行时间日期不同 | 报告时间不一致，拒绝一致性判断；不当成独立来源 |
| 用 JSON 字符串比较输入对象使属性顺序影响结果 | 浏览器刷新固定示例实际报“输入已变化” | 按 text / symbol / window 字段逐项比较 |
| 初版测试把真实时间不一致误当成报价冲突 | 自动测试实际返回 `time_mismatch` | 冲突测试显式构造同日样本；保留真实时间不一致行为 |
| 客户端可改计划并伪造模型记录 | 检查确认后的请求路径 | HMAC-SHA256 计划票据，20 分钟有效，输入变动拒绝 |
| 时间显示容易丢失时区语义 | 对比原始 timestamp 与行时间 | 展示源时点与抓取时间，并说明 Asia/Shanghai 和就绪时间的含义 |
| 缺失字段或负 PE 易被解释为正常“低估” | null、负值、零值、分母为零测试 | 不补零；非正 PE 不作正常估值解释 |

这是开发过程中的校验与修正记录，不冒称用户已审核代码或产品质量。用户明确同意公开评审版；未收到模型服务密钥时，自定义 LLM 实测不能标为已完成。

## 验证范围与尚未证明的部分

- 真实取数样例与固定规划在线刷新已经运行；模型契约的自动测试使用模拟 JSON，明确不能证明某个真实模型的语义准确率。
- 页面会明确区分回放、固定规划在线取证、AI 规划在线取证、人工故障演练。
- 本次 Codex 辅助开发不等于“产品已通过真实用户效果验证”。用户访谈、30 段配对实验与合规文本红队仍为后续计划。
- 没有人工虚构市场数值、LLM 运行成功记录、访谈结果或效率提升百分比。数值样例可从原始响应独立复算。
